# @vexa-video/core

Backend-neutral types, serializable media/project/job schemas, validation helpers, and browser-safe shared contracts for Vexa Video SDK.

Version 2 composition foundations also live here: `defineComposition()`, `defineStill()`, deterministic static metadata serialization, runtime prop validation, dynamic metadata calculation, and `ProgrammableCompositionRegistry` discovery. The shared programmable-timing runtime adds explicit frame contexts, frame/second conversion, interpolation, easing, color interpolation, analytic springs, seeded random values, loop/freeze helpers, series offsets, and frame-range utilities. The programmable-scene runtime adds nested groups/layers, media/text/fill/surface intent, deterministic z/timing normalization, asset manifests/readiness, storage-aware references, shape/effect/transition contracts, and typed lowering of representable scenes into `VideoProjectAst`. Visual scene leaves can carry normalized programmable transition pairs for fade, slide, wipe, push, zoom, and circular iris authoring; the same fade contract now lowers unchanged into representable project clips for backend execution, while the remaining transition families stay explicitly fail-closed. Image/video/text project clips preserve normalized programmable effect chains for backend execution, while unsupported visual-node lowering remains explicit. The executable-composition contract pairs those definitions with a browser-safe scene factory, resolves props and dynamic metadata before evaluation, validates returned scene metadata, and provides a deterministic executable registry for renderer loading. These contracts do not depend on React, DOM execution, Node execution, FFmpeg, or a bundler.

Use `@vexa-video/core/browser` from browser/framework code for serializable public types, pure composition definition/resolution helpers, and deterministic timing/scene runtime helpers. This entry point is the shared foundation for browser adapters such as `@vexa-video/react`.
