# Vexa Video SDK v2.0.0

Vexa Video SDK 2.0 adds a Vexa-native programmable-video layer while preserving the existing deterministic media, timeline, storage, job, hardware, and FFmpeg execution foundations.

## Highlights

- code-defined compositions with deterministic frame/time/animation semantics, scene graphs, validated props, dynamic metadata, and reusable templates;
- browser-safe React authoring, Player, and Studio surfaces with TypeScript/TSX bundling and composition discovery;
- local Node still/frame/video rendering plus provider-neutral hosted rendering through the existing job and storage contracts;
- browser/WebCodecs rendering with capability/fallback planning, H.264/AAC MP4 and VP9-or-AV1/Opus WebM paths, Canvas/serializable-DOM capture, progress, cancellation, and Blob/File output;
- shapes, effects, transitions, fonts, captions, GIF, waveform, and sound-effect integrations without creating a second media engine;
- typed CLI and MCP composition workflows plus frame-level visual regression, browser-pixel parity, and frame-derived media duration/A/V-sync acceptance.

## Release hardening

All eighteen public `@vexa-video/*` packages share the `2.0.0` version. Release acceptance packs and clean-installs the real tarballs on Ubuntu 24.04, Windows, and macOS, runs Node 26 compatibility on Ubuntu 24.04, and exercises Studio in Chrome across all three operating systems plus Microsoft Edge on Windows.

The protected release path requires FFmpeg/ffprobe 6.1+ with `drawtext`, `libx264`, and AAC, and uses GitHub Actions OIDC trusted publishing with npm provenance. Token-backed `NPM_TOKEN` and `NODE_AUTH_TOKEN` publication is rejected.

## Upgrade notes

Upgrade all Vexa packages used by an application together rather than mixing the synchronized 1.x and 2.0.0 package sets. Browser packages must remain isolated from Node/FFmpeg execution code.

See [Migrating to Vexa Video SDK 2.0](../V2_MIGRATION.md) for the package/runtime checklist.
