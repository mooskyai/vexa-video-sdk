# Version 2 Baseline and Version 3 Direction

This document explains the boundary between the released Version 2 platform and the planned Version 3 production-platform work.

## Version 2 is the stable baseline

Vexa Video SDK `2.0.0` is released from source commit:

```text
af8d1d8e0c967e2651b8f77c1e02b6f11135a90a
```

Version 2 established:

- deterministic media/timeline/audio/caption/streaming execution;
- programmable compositions and deterministic animation/timing;
- React authoring, Player, Studio and browser rendering;
- TypeScript/TSX bundling and Node composition rendering;
- templates, graphics, transitions, fonts and composition captions;
- hosted-render contracts, jobs, storage publication and retries;
- CLI/MCP/agent workflows;
- plugin and provider-neutral AI extension layers;
- deterministic visual/runtime regression testing;
- protected cross-platform release qualification and npm provenance.

Applications can build on these contracts now. Version 3 is not required to use Vexa in production, but some large-scale operational features remain application responsibilities in 2.0.0.

## Version 3 is additive

Version 3 does **not** replace the Version 2 composition or render contract. It hardens and scales it.

The main V3 themes are:

1. worker resilience and recovery;
2. capability-aware scheduling;
3. render caching and resumability;
4. deeper GPU pipelines;
5. professional editor semantics;
6. proxy/preview optimization;
7. richer graphics and motion systems;
8. expanded AI editing;
9. first-party cloud media adapters;
10. Streaming 2.0;
11. project-format evolution;
12. collaboration contracts;
13. hosted-render platform controls;
14. broader framework/service integrations;
15. plugin ecosystem expansion;
16. V3 release qualification.

## Existing foundations must be reused

Several V3 areas already have Version 2 foundations. The V3 plan must extend them rather than create parallel systems:

| V3 area | Existing Version 2 foundation |
| --- | --- |
| Worker hardening | local/Redis jobs, retries, idempotency, cancellation |
| Scheduling | hardware detection, job descriptors, distributed transport |
| Render cache | deterministic plans, composition metadata, artifact identity |
| Hardware | NVENC/QSV/AMF/VideoToolbox verification + CPU fallback |
| Editor | `@vexa-video/editor` and Studio timeline state |
| Preview/proxies | Player, Studio, browser renderer |
| Graphics | shapes, typography, effects, transitions, captions |
| AI | transcription, scene detection, silence removal, smart reframe, highlights |
| Cloud media | storage adapter hooks |
| Streaming | HLS/DASH, renditions, aligned segments, preview sprites |
| Hosted platform | hosted requests, jobs, progress/cancel, storage publication |
| Frameworks | Angular and React packages |
| Plugins | lifecycle-managed plugin host and explicit extension points |
